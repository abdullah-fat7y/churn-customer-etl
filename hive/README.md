# Hive Queries

This folder contains the HiveQL queries used to create, validate, test, and analyze the **Gold layer** of the Customer Churn ETL Pipeline.

The main Hive script is:

```text
hive/
└── gold_hive_queries_test.hql
```

The script works with the Gold datasets generated by `silver_to_gold.py`.

---

# Hive Layer

The Gold data is stored in HDFS as Parquet files:

```text
/data/gold/dim_customer
/data/gold/fact_customer_activity
/data/gold/monthly_churn_rate
```

Hive creates external tables on top of these HDFS locations:

```text
dim_customer_gold
fact_customer_activity_gold
monthly_churn_rate_gold
```

The overall flow is:

```text
Bronze
   │
   ▼
bronze_to_silver.py
   │
   ▼
Silver
   │
   ▼
silver_to_gold.py
   │
   ▼
Gold Parquet
   │
   ▼
Hive External Tables
   │
   ▼
HiveQL Analytics
```

---

# Running the Hive Script

The complete HiveQL file can be executed with:

```bash
hive -f ~/Desktop/gold_hive_queries_test.hql
```

The script creates the database and external tables, performs validation tests, and executes the business analysis queries.

---

# 1. Create the Hive Database

The script creates the project database if it does not already exist:

```sql
CREATE DATABASE IF NOT EXISTS churn_gold;
```

Then it selects the database:

```sql
USE churn_gold;
```

The database contains the Gold external tables used for analytics.

---

# 2. Create External Gold Tables

The script removes old table definitions and recreates them as external tables.

## dim_customer_gold

This table represents the customer dimension.

Main fields include:

```text
cust_key
customer_id
is_churned
CLV_LTV
avg_ticket_res_time_hrs
num_products
dw_start_date
dw_end_date
```

Location:

```text
hdfs:///data/gold/dim_customer
```

---

## fact_customer_activity_gold

This table contains monthly customer activity.

Main fields include:

```text
customer_id
activity_month
usage_events
total_balance
avg_balance
ticket_count
avg_resolution_time
offer_count
accepted_offers
acceptance_rate
cust_key
activity_key
```

Location:

```text
hdfs:///data/gold/fact_customer_activity
```

Each record represents customer activity for a specific month.

---

## monthly_churn_rate_gold

This table contains monthly churn results.

Main fields:

```text
activity_month
active_customers
churned_customers
churn_rate
```

Location:

```text
hdfs:///data/gold/monthly_churn_rate
```

# 3. Basic Table Tests

The script performs simple checks to make sure the Hive tables exist and contain data.

### Show Tables

```sql
SHOW TABLES;
```

This confirms that the Gold tables have been created in `churn_gold`.

### Preview Customer Dimension

```sql
SELECT * FROM dim_customer_gold LIMIT 10;
```

Displays sample customer records.

### Preview Activity Fact

```sql
SELECT * FROM fact_customer_activity_gold LIMIT 10;
```

Displays sample monthly activity records.

### View Monthly Churn

```sql
SELECT * FROM monthly_churn_rate_gold
ORDER BY activity_month;
```

Displays the monthly churn results in chronological order.

---

# 4. Row Count Validation

The script counts the rows in all three Gold tables:

```sql
SELECT 'dim_customer' AS table_name, COUNT(*) AS row_count
FROM dim_customer_gold

UNION ALL

SELECT 'fact_customer_activity', COUNT(*)
FROM fact_customer_activity_gold

UNION ALL

SELECT 'monthly_churn_rate', COUNT(*)
FROM monthly_churn_rate_gold;
```

This provides a quick summary of the amount of data available in each Gold dataset.

---

# 5. Gold Key Validation

The next queries validate the uniqueness and completeness of the Gold keys.

## Null Customer Keys

Checks whether `cust_key` contains null values:

```sql
SELECT COUNT(*)
FROM dim_customer_gold
WHERE cust_key IS NULL;
```

Expected result:

```text
0
```

## Duplicate Customer Keys

Checks whether multiple records use the same `cust_key`.

## Duplicate Customer IDs

Checks whether a customer appears more than once in the customer dimension.

## Null Activity Keys

Checks whether `activity_key` contains null values.

## Duplicate Activity Keys

Checks whether multiple fact records share the same `activity_key`.

## Duplicate Customer + Month

Checks that a customer does not have more than one fact record for the same:

```text
customer_id + activity_month
```

These tests help confirm that the Gold layer follows the expected dimensional-model structure.

---

# 6. Foreign Key Validation

The following query checks for orphan fact records:

```sql
SELECT COUNT(*) AS orphan_fact_rows
FROM fact_customer_activity_gold f
LEFT JOIN dim_customer_gold d
    ON f.cust_key = d.cust_key
WHERE d.cust_key IS NULL;
```

The goal is to ensure every fact record has a matching customer dimension record.

Expected result:

```text
0
```

# Business Analysis Queries

The Hive script contains **13 business questions** designed to analyze customer value, churn, engagement, support activity, offers, and retention.

---

# 7. Business Question 1
## Who Are Our Highest-Value Customers?

This query returns the top 10 customers based on `CLV_LTV`.

It displays:

```text
customer_id
CLV_LTV
num_products
is_churned
```

The results are sorted by lifetime value in descending order.

Purpose:

- Identify the most valuable customers
- See how many products they have
- Check their churn status

---

# 8. Business Question 2
## Are High-Value Customers at Risk of Churn?

Customers are divided into three value segments:

```text
CLV_LTV >= 10000  → High Value
CLV_LTV >= 1000   → Medium Value
Otherwise         → Low Value
```

The query calculates:

```text
customers
churned_customers
churn_rate
```

The result helps compare churn behavior across customer-value segments.

---

# 9. Business Question 3
## Which Months Have the Highest Churn?

The query reads from:

```text
monthly_churn_rate_gold
```

and returns the top five months with the highest churn rate.

It displays:

```text
activity_month
active_customers
churned_customers
churn_percentage
```

Purpose:

- Identify periods with unusually high churn
- Help detect seasonal or operational problems

---

# 10. Business Question 4
## How Is Customer Churn Trending?

This query returns monthly churn results ordered by:

```text
activity_month
```

It shows:

```text
activity_month
active_customers
churned_customers
churn_percentage
```

Purpose:

- Track churn over time
- Identify increasing or decreasing churn trends

---

# 11. Business Question 5
## Which Customers Generate the Most Support Tickets?

The fact table is joined with the customer dimension using:

```text
cust_key
```

The query calculates:

```text
total_tickets
avg_resolution_time
CLV_LTV
is_churned
```

It returns the top 10 customers with the highest number of support tickets.

Purpose:

- Identify customers requiring high support effort
- Compare support activity with customer value
- Examine whether heavily supported customers are churned

---

# 12. Business Question 6
## Does Support Resolution Time Relate to Churn?

Customers are grouped according to average support resolution time:

```text
Less than 24 hrs
24-48 hrs
48+ hrs
```

For each group, the query calculates:

```text
customers
churned_customers
churn_rate
```

Purpose:

- Investigate whether slower support resolution is associated with higher churn
- Identify support-performance groups with greater churn

---

# 13. Business Question 7
## How Effective Are Our Offers?

The query calculates overall offer performance:

```text
total_offers
accepted_offers
acceptance_rate
```

The acceptance rate is calculated from:

```text
accepted_offers / total_offers
```

The query also prevents division by zero when there are no offers.

Purpose:

- Measure offer performance
- Understand customer response to offers

---

# 14. Business Question 8
## Does Number of Products Affect Customer Value?

Customers are grouped by:

```text
num_products
```

For each product-count group, the query returns:

```text
customers
avg_clv
churn_rate
```

Purpose:

- Compare customer value by number of products
- Examine whether customers with more products have different churn behavior

---

# 15. Business Question 9
## Does Customer Balance Relate to Churn?

First, the query calculates total customer balance across activity records.

Customers are then grouped into:

```text
High Balance
    total_balance >= 10000

Medium Balance
    total_balance >= 1000

Low Balance
    total_balance < 1000
```

The query calculates:

```text
customers
churned_customers
churn_rate
```

Purpose:

- Compare churn among balance segments
- Determine whether customer balance is associated with churn

---

# 16. Business Question 10
## Does Customer Engagement Relate to Churn?

Customer usage is aggregated across the fact table.

Customers are divided into:

```text
Highly Engaged
    total_usage >= 20

Moderately Engaged
    total_usage >= 5

Low Engagement
    total_usage < 5
```

The query returns:

```text
customers
churned_customers
churn_rate
```

Purpose:

- Measure the relationship between customer activity and churn
- Identify low-engagement customers

---

# 17. Business Question 11
## Does Having More Products Reduce Churn?

Customers are grouped by:

```text
num_products
```

The query calculates:

```text
customers
churned_customers
churn_rate
average_clv
```

Purpose:

- Compare churn across product ownership levels
- Determine whether product adoption is associated with customer retention
- Compare customer lifetime value across groups

---

# 18. Business Question 12
## Retention Priority Customers

This query identifies active customers who may require retention attention.

The query selects customers who satisfy all of the following:

```text
is_churned = 0
CLV_LTV >= 1000
total_usage < 5
```

The result includes:

```text
customer_id
CLV_LTV
num_products
total_usage
total_tickets
is_churned
```

The results are ordered by `CLV_LTV` and limited to the top 20.

Purpose:

- Find valuable customers with low engagement
- Prioritize customers for retention campaigns

---

# 19. Business Question 13
## Customer Churn Risk Segmentation

This query creates business-oriented customer segments using:

```text
is_churned
CLV_LTV
total_usage
```

The segmentation rules are:

```text
Already Churned
    is_churned = 1

High Value - High Risk
    CLV_LTV >= 10000
    total_usage < 5

Medium Value - High Risk
    CLV_LTV >= 1000
    total_usage < 5

Highly Engaged
    total_usage >= 20

Stable Customer
    all remaining customers
```

For each segment, the query returns:

```text
customer_segment
customers
average_clv
average_usage
average_tickets
```

Purpose:

- Create actionable customer segments
- Identify high-value customers at risk
- Compare engagement and support activity across segments

---

# 20. Final Gold Summary

The final query provides a row-count summary of the Gold datasets:

```sql
SELECT 'DIM CUSTOMER' AS dataset, COUNT(*) AS rows
FROM dim_customer_gold

UNION ALL

SELECT 'FACT CUSTOMER ACTIVITY', COUNT(*)
FROM fact_customer_activity_gold

UNION ALL

SELECT 'MONTHLY CHURN RATE', COUNT(*)
FROM monthly_churn_rate_gold;
```

This gives a final overview of the number of records in:

```text
dim_customer_gold
fact_customer_activity_gold
monthly_churn_rate_gold
```

# Summary

`gold_hive_queries_test.hql` provides the Hive layer for the Customer Churn ETL Pipeline.

It performs three main jobs:

```text
1. Create Hive external tables over Gold Parquet data

2. Validate the Gold layer
   - Row counts
   - Null keys
   - Duplicate keys
   - Duplicate customer/month records
   - Orphan fact records

3. Perform business analysis
   - Customer value
   - Churn trends
   - Support activity
   - Offer effectiveness
   - Product adoption
   - Customer balance
   - Customer engagement
   - Retention priorities
   - Churn risk segmentation
```

The final output provides a SQL-based analytics layer on top of the Gold datasets.
